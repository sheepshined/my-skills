# 学习手册章节模板

本模板定义学习手册章节的结构与每节写作要求。编号用占位符 `X`：追加到现有文档时沿用其章节序号（如入口文档用"八、"则本章为 8.1~8.7；入口文档用 "Part n" 或无编号则直接用 X.1~X.7 并在章首注明）；独立成文件时从 1 开始。所有表格列数与顺序不要改，内容按项目填充；不适用的小节可整节省略，但 **X.1~X.4（概念地图/路线/精读/实验）是核心四件，快档至少保留概念地图、路线、实验三节，慢档七节全写**。

---

## X.0 开头引言（3 行内）

> 一句话说明本章回答"怎么学"；总预算天数；一条学习原则。

原则的固定句式：**先跑通、再主线、后支线；每阶段动手做一次实验，不做"只读不练"的学习。**

## X.1 前置知识地图（概念 → 项目落点）

分后端/前端两张表（纯后端或纯前端项目只留一张）。每行 3 列：

| 概念 | 一句话解释 | 本项目落点 |
|---|---|---|

- 概念范围：框架核心机制（依赖注入/状态机/组合式函数…）+ 领域关键词（RAG/RRF/JWT…），共 20~30 个，挑"不懂它就读不懂主线"的。
- 落点必须精确到文件（关键处到函数/行号），一句话解释 ≤30 字。
- 这张表的作用是让抽象概念立刻有实物对应，用户"用到哪补哪"。

## X.2 分阶段学习路线

按阶段组织，每阶段四要素：**预算天数｜读什么/做什么｜主线问题｜通关检验**。

- 阶段 0 永远是"跑起来并点通全流程"：启动、走一遍核心流程、开调试工具（F12/日志/docs）看一次运行时现象。通关检验 = 不看文档能复述流程。
- 中间阶段沿主线组织（"一次请求/一条消息/一个任务的生命周期"），每阶段聚焦 1~2 个子系统。
- 末阶段固定是"测试与工程视角"：跑测试套件、精读 2~3 个代表性测试。
- 总预算 4~6 天（中型项目），小型项目压到 2~3 天。
- **通关检验**每阶段 2~5 个问题，必须满足：答案在代码里（考理解）、覆盖该阶段最核心的机制、包含至少一个"为什么这样设计/为什么不那样"的取舍题。
- 通关检验问题要顺手给出答案线索的 file:line（括号提示，如"（resume 从节点头重跑）"）。

## X.3 精读代码清单

| # | 位置 | 学什么 / 为什么必读 |
|---|---|---|

- 10~20 段（小项目可 6~10），按学习优先级排序：最小可闭环文件（如协议/常量表）→ 状态定义 → 核心机制（引擎节点/主循环）→ 工程兜底（容错/降级/校准）→ 前端对应件。
- 位置写 `文件:行号 函数名`；行号写完逐条核对一遍（至少确认函数起始行准确）。
- "学什么"一句话点破该段的"机制名 + 解决的问题"，例如"自一致性集成：总分/四维取中位数、得分点过半投票"。
- 表末加一句："其余文件按 X.2 阶段路线顺带读，不必逐行。"

## X.4 动手实验清单

| 实验 | 改动 | 预期现象与理解点 |
|---|---|---|

- 6~10 个（L1、L2…编号），素材主要来自配置层可调参数 + 白名单/阈值/开关类常量。
- 每个实验：改动精确到 `文件:行号`；预期现象具体可观察（界面/日志/测试/输出变化）；"理解点"点破它验证的概念。
- 表头下紧跟**守则**：实验只改工作区不提交；每做完一个回到对应阶段解释"为什么出现这个现象"；标注回滚方式——已跟踪文件 `git checkout -- <file>`；实验新建的文件直接删除；非 git 项目把原值抄进实验说明里。
- 至少含 1 个"破坏性实验"（删白名单/改鉴权让测试变红），让用户看到保护网如何工作；项目没有测试套件时，替代写法是直接调用被破坏的函数/接口观察行为变化（python -c / node -e / curl）。

## X.5 常见疑问预答（FAQ）

- 10~15 条，全部是 **why/取舍类**："为什么 X 而不是 Y""X 的代价是什么""X 之后 Y 会怎样"。
- 最佳素材：代码注释里已经写明的设计取舍（如防幻觉的数据契约）、架构上的"反直觉点"（进程内状态 vs 持久化、为什么拆两个存储）、刚修过的坑。
- 每条 ≤6 行，先一句结论再展开；结尾标依据 file:line。
- 禁止百科式科普；只答"这个项目为什么这样"。

## X.6 观测与调试手段速查

| 想看什么 | 手段 |
|---|---|

- 6~10 行：接口调试入口、运行时消息/日志观测点、持久化文件（db/落盘产物）怎么查、单测怎么跑、专项回归脚本。
- 表后附"排查口诀补充"：3~5 条"症状 → 先查哪"（症状用用户视角描述，如"面试卡住""图谱聚团""报告没生成"）。

## X.7 其他文档导读

| 文档 | 定位 | 建议 |
|---|---|---|

- 对根目录/文档目录里除入口文档外的每份文档给三档定性：可读（但哪部分过时）/ 历史档案（何时有用）/ 可忽略。
- 收尾一句："当前唯一反映项目现状的就是 [入口文档] + 代码本身"，防止用户学到旧信息。

## 收尾动作（写完手册后）

1. 追加到入口文档的场景：回到入口文档的"阅读路径"表追加一行指向本章（无此表则在文档头部引言里加一句导流）。新建 `LEARNING_GUIDE.md` 的场景：在新文件头部自带"阅读路径"表，并确认入口文档头部已加交叉引用。
2. 若发现并修正了事实错误，在本章末尾加"核实与修正记录"小节列明（错误 → 改为 → 依据），增强文档可信度。
3. 自查：精读清单的 file:line 逐条核对、其余引用抽查 3 处；每个通关检验问题在代码中确有答案；每个实验标注了回滚方式。
