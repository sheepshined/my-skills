# Agent 产品架构契约

## 一、先分配自主性

| 机制 | 使用条件 | 不要拿它解决 |
|---|---|---|
| Workflow / StateGraph | 阶段、顺序、终止条件已知，要求可预测与可回放 | 用大量 prompt 模拟固定流程 |
| 单 Agent | 工具选择、调用次数或信息路径需要动态决定 | 固定 CRUD、简单路由 |
| Skill | 多次复用的程序性知识，需要按需加载和独立评测 | 新工具连接、一次性项目约定 |
| MCP / API 工具 | 需要连接外部系统、数据或执行能力 | Agent 的决策与流程本身 |
| 多 Agent | 任务可分解、上下文隔离有收益、子任务能独立验收 | 用角色扮演掩盖单 Agent 设计不清 |

默认顺序：**确定性函数 → workflow → 单 Agent → Skill 化复用流程 → 有证据时再多 Agent**。不要用框架名气替代这层判断。

## 二、画清系统边界

至少画出以下边界：

1. 用户入口与前端状态。
2. Agent 编排层与稳定业务内核。
3. 模型可见工具与服务端实际执行面。
4. 读操作、写操作、高代价执行操作。
5. 短期会话、checkpoint、长期记忆与原始业务数据。
6. 模型生成内容与确定性计算结果。

优先通过适配器调用既有内核。若两个图或两个执行域需要协作，使用显式事件、提案或 handoff 契约，避免互相隐式调用和共享可变状态。

## 三、LangGraph 与状态机检查

实装 API 以当前依赖源码为准。无论采用何种框架，都检查：

- 等待用户输入的节点在挂起点之前没有随机选择、LLM 调用、写库、写文件或外部副作用。
- 恢复执行不会重复选题、重复发送、重复写入或重复扣费。
- 准备副作用与等待输入拆成可独立测试的阶段。
- 每次恢复都校验用户、会话、当前 phase 和操作 ID。
- 每个模型 tool call 都有且仅有一个配对结果，包括未知工具、拒绝、异常和超限路径。
- 同一操作重复批准、重复拒绝或重复回调不会再次产生副作用。
- 需要串行的写操作有明确互斥、事务或版本检查，不能依赖模型自觉。

## 四、工具与权限契约

每个工具至少定义：

```text
name / description / input schema / output schema
risk=read|write|execute / needs_approval / timeout
identity source / tenant filter / side effect / idempotency
max output size / error shape / trace fields
```

遵守：

- 身份由服务端认证上下文注入，不接受模型自报 username。
- 工具描述写清“何时用、何时不要用”，让路由可评测。
- 高代价动作先生成可编辑提案，再由用户批准原操作；模型不得绕过提案直接执行。
- 审批绑定用户、会话、操作和参数指纹；参数改变后重新审批。
- 批准与拒绝都返回配对消息，模型不得把“已提案”说成“已执行”。
- 技能、提示词、检索文档和 JD 都视为数据，不得覆盖系统权限与安全规则。

## 五、记忆与上下文

区分四类信息：当前轮输入、会话历史、可恢复状态、跨会话长期记忆。

长期记忆至少需要：

- 来源、时间、重要度、可信度和可删除性。
- 写入门槛，避免把闲聊、模型推断和已注入记忆反复写回。
- 冲突更新或 supersede 策略。
- 检索降权和召回上限，避免旧记忆永久主导上下文。
- 用户可见、可删、可清空。

压缩前检查 tool call 配对和待确认状态；保留 UI 完整历史与模型精简上下文之间的区别。压缩失败不得破坏已经完成的消息。

## 六、RAG 与证据链

先明确检索对象与业务题库是否必须物理隔离，再设计：

- 切分与返回单位：小块负责命中，父块或原文负责上下文完整性。
- 关键词与向量召回的分工，以及融合、去重、截断策略。
- 数据增删改后的索引同步、失败降级与重建路径。
- 答案引用到原始文档、父块或报告 ID 的路径。
- 无结果、低相关、越权、损坏文档和索引不可用时的行为。

先建立固定探针与基线，再调整 chunk、top-k、权重或阈值。没有 Recall/Hit/MRR、忠实度或人工判据支撑，不宣称“检索更准”。

## 七、架构评审出口

提交方案前回答：

- 哪一层真正需要自主性，为什么？
- 哪些稳定内核完全不改？
- 哪个组件拥有每份状态？
- 哪些操作可重放，哪些必须幂等？
- 每个副作用如何被授权、追踪和恢复？
- 哪些机制断言有 `file:line` 或实测，哪些仍待验证？
- 最小端到端验收剧本是什么？
